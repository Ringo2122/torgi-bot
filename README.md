# Сторож торгов

Telegram-бот: следит за новыми лотами недвижимости и транспорта на **e-auction.by** (БелЮрОбеспечение)
**ipmtorgi.by** (ИПМ-Торги), **beltorgi.by** (Белреализация), **cpo.by** (Центр промышленной оценки) и **konfiskat.by**
(Торговый дом «Восточный»). По каждому новому лоту присылает название, фотографию, стартовую цену
и дату окончания приёма заявок.

Работает автономно на сервере, Claude для этого не нужен.

## Что сторожит

| Площадка | Раздел |
|---|---|
| e-auction.by | Недвижимость |
| e-auction.by | Легковые авто |
| e-auction.by | Грузовые и автобусы |
| ipmtorgi.by | Недвижимость |
| ipmtorgi.by | Транспорт и спецтехника |
| beltorgi.by | Недвижимость |
| beltorgi.by | Легковые авто |
| beltorgi.by | Грузовые авто и автобусы |
| cpo.by | Недвижимость |
| cpo.by | Транспорт и спецтехника |
| konfiskat.by | Автотранспорт (аукционы) |
| konfiskat.by | Недвижимость (аукционы) |

**Дубли.** ЦПО показывает на своём сайте те же торги, что проводит на ИПМ. Лот с тем же названием и
стартовой ценой, уже встреченный на другой площадке, бот не присылает повторно (подписи `sig|…` в памяти).
На konfiskat.by в списке только дата аукциона: заявки по извещениям — до 12:00 накануне.

Цена, дата и фото берутся прямо из списка лотов. Исключение — beltorgi.by: список там
подгружается скриптом (POST `/assets/category.php`), а вместо срока заявок показан
обратный отсчёт. Поэтому за точным сроком бот заходит в каждый **новый** лот beltorgi.
Каждый раздел читается целиком, все страницы с активными лотами: около 50 запросов
и две-три минуты на цикл. Читать только первую страницу нельзя — ИПМ-Торги
сортируют по сроку приёма заявок, и старые лоты «въезжают» на первую страницу,
а новые с коротким сроком оказываются на второй и дальше.

## Установка на сервер

Подойдёт любой VPS с Debian или Ubuntu, хватит самого дешёвого.
Если в планах подключить fcon.by, promtorgi.by, auction24.by или elot.by — сервер нужен
в Беларуси: извне эти площадки не отвечают.

```bash
scp -r torgi-bot root@ВАШ_СЕРВЕР:/tmp/
ssh root@ВАШ_СЕРВЕР
sudo bash /tmp/torgi-bot/install-server.sh
```

Скрипт поставит ruby и curl, заведёт системного пользователя `torgi`, положит бота
в `/opt/torgi-bot`, данные в `/var/lib/torgi` и зарегистрирует systemd-таймер.
Дальше он выведет три оставшихся шага — их делает владелец бота.

## Токен

Токен выдаёт [@BotFather](https://t.me/BotFather) по команде `/newbot`.
Он **не хранится в коде и не передаётся в переписке**: положите его файлом на сервере.

```bash
sudo -u torgi tee /var/lib/torgi/token >/dev/null   # вставить токен, затем Ctrl-D
sudo chmod 600 /var/lib/torgi/token
```

Затем напишите своему боту в Telegram любое сообщение — бот сам определит, кому слать,
и запомнит это в `/var/lib/torgi/chat_id`.

## Запуск

```bash
# проверить связь с Telegram
sudo -u torgi TORGI_HOME=/var/lib/torgi ruby /opt/torgi-bot/tgbot.rb --test

# запомнить текущие лоты и НИЧЕГО не слать (обязательно перед первым включением)
sudo -u torgi TORGI_HOME=/var/lib/torgi ruby /opt/torgi-bot/tgbot.rb --init

# включить проверку каждые 15 минут
sudo systemctl enable --now torgi-watcher.timer
```

Без шага `--init` при первом запуске сработает предохранитель: придут 25 сообщений, остальные лоты молча запомнятся.

## Режимы

| Команда | Что делает |
|---|---|
| `tgbot.rb` | обычный цикл: прислать только новые лоты |
| `tgbot.rb --init` | запомнить текущие лоты, ничего не отправлять |
| `tgbot.rb --test` | проверить токен и отправить тестовое сообщение |
| `tgbot.rb --dry` | показать, что собралось, без отправки |

## Наблюдение

```bash
systemctl list-timers torgi-watcher.timer
journalctl -u torgi-watcher.service -n 50 --no-pager
sudo tail -n 30 /var/lib/torgi/bot.log
```

## Настройки

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `TORGI_HOME` | `~/.torgi` | каталог с токеном, памятью и логом |
| `TG_TOKEN` | — | токен вместо файла (для разовых запусков) |
| `MAX_SEND` | `25` | предохранитель: не больше сообщений за цикл |

Частота проверки меняется в `/etc/systemd/system/torgi-watcher.timer`
(`OnUnitActiveSec`), после правки — `systemctl daemon-reload`.

Разделы задаются списком `SECTIONS` в начале `tgbot.rb`.

Из админки сайта (https://ringo2122.github.io/bellot-site/admin/ → Telegram-бот) можно поставить бота
на паузу и выключить отдельные разделы: такие лоты бот запоминает, но не присылает. После каждой
проверки бот пишет туда отчёт — сколько отправлено и по каким площадкам. Связь — переменные
`SB_URL`, `SB_KEY`, `SB_TOKEN` (секреты GitHub); без них или при сбое базы бот работает как раньше.

## Что внутри устроено на всякий случай

- **Память лотов** — `/var/lib/torgi/seen.json`, записи старше 120 дней вычищаются.
- **Предохранитель** — если вдруг «новых» оказалось больше 25, отправятся первые 25,
  остальные пометятся прочитанными. Защита от ситуации, когда площадка сменила вёрстку
  и все лоты выглядят новыми.
- **Блокировка** — `/var/lib/torgi/lock`, чтобы два запуска не наложились.
- **Часовой пояс** прибит к `Europe/Minsk`: площадки печатают минское время без указания
  зоны, а сервер обычно живёт в UTC.
- **Если площадка не ответила** — цикл не падает, в лог уходит строка, лоты этого раздела
  просто не обновляются.
